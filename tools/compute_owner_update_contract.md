# Three compute-owner update data contract v1

The generic tool reads one immutable JSON contract and an explicit SHA256. `plan` is offline; `deploy` and `accept` are explicit live actions. This contract grants no automatic mode, motion, scene clearance or new hands-clear assertion. Old full regression and current focused verification are different evidence roles. No old resume context or AST generation patch is used.

Top-level fields (required unless noted):

- `schema: 1`, `kind: "three_compute_owner_update"`, `release_label`: nonempty human label.
- `workspace_root`, `candidate_root`, `storage_root` (mounted SanStand), `output_root`: absolute paths. Candidate may be a sparse overlay; unchanged source comes from the installed baseline.
- `reference`: `{ "epoch_ns": positive integer, "selection": {"mode":"unknown", "strategy":"observe_return", "generation": nonnegative integer, "stamp_ns": positive integer} }`. Must equal the closed post-attempt reference. This is an expectation, never freshness proof.
- `refs`: named `{path,sha256}` references: `baseline_release`, `baseline_acceptance`, `baseline_reload`, `baseline_bundle`, `baseline_construction`, `post_attempt`, `baseline_full`, `targeted`, `review`, `adoption`, `startup_configuration`, `startup`, `core_reference`, `gateway_service_design`. All are explicitly historical. Referenced current client/config/source/code is classified separately.
- `authorization`, `control`, `archive_config`, `storage_control`: current `{path,sha256}` references. Current control must be active and linked to authorization. `control_events` is an ordered list (empty if unchanged since acceptance) of `{snapshot:ref, request:ref}` sealed explicit user-control transitions; only an actual user resume can reactivate a paused snapshot.
- `current_sha256`: canonicalizable path -> SHA map for live authorization/control/config/helper/module inputs. Every currently executing module and all transitive non-standard-library helper sources belong here. Current/source paths cannot be classified historical.
- `historical_sha256`: explicit closed evidence path -> SHA map. Must contain `refs`, `control_events` and the finite references needed by their checks. It is read once per transaction. No workspace source, candidate source, active control or executing helper may be here. Baseline release is trusted as a sealed historical artifact; the tool does not recursively re-run every old helper.
- `modules`: roles `runtime`, `base`, `identity`, `verifier`, `old`, `checker`, `installer`, `preloader`, each a current `{path,sha256}` reference to an already-reviewed primitive module. `module_dependencies`: ordered list of current references loaded first under their file stem (for verified source imports, not pyc). Existing GEN-named modules remain immutable primitive libraries, never a new wrapper.
- `source_update`: `{production: [relative paths], tests: [relative paths], candidate_sha256: {relative path:sha}}`. Candidate map covers exactly production plus changed/added tests; the complete resulting release map is baseline plus these entries. Production and tests must be disjoint. Targeted summary must bind the same production/test bytes.
- `starter`: current reference to the generic `compute_owner_start.py`. Generic entry and `runtime_evidence.py` must also be current pins.

Cross-artifact checks retain accepted 17 identities, exact three updated owners and fourteen retained identities, original units, launch respawn/required false, startup environment/load resolution, core/master/simulation bindings, existing 31 gateway services, current remote construction configuration, baseline source map and exact installed candidate delta. Post-attempt must bind the same accepted release/instances and a returned, closed authorized selection transition. Prior artifacts establish expected state; live graph, SDK20, GUI own manual ACK, CONFIRMED, idle/actions, source/config and configured remote health still run at boundaries.

`targeted` is the existing finite-result summary: `passed`, `production_sha256`, `current_test_sha256`, exact `case_results`, zero omissions/duplicates, `full_regression_passed:false`. `review` binds exact candidate production bytes; `adoption` binds the same source map and gateway compatibility. `baseline_full` must match baseline release source map and actual full-run reference; it is never relabelled as a full run of this candidate.

Receipt kinds are `three_compute_owner_update_plan`, `three_compute_owner_construction`, `three_compute_owner_reload`, `three_compute_owner_acceptance`, and `compute_owner_source_start`, with separate `release_label`. A failure preserves partial state and does not retry, rollback, disable joints or change mode.

One transaction keeps a bounded 80-message SDK callback window. Each boundary checks the latest 20 ordered unique real measurements against the original 200 ms freshness and 0.004 rad stability/reference limits, after verifying current files. Driver or epoch changes invalidate the transaction. Latched state is refreshed at each boundary; reusing subscriptions does not renew a reference or authorize motion.

Optional `declared_readonly_observers` contains exact node/URI/process/source/subscription/standard-service declarations validated by a current `observer_module` reference. `readonly_observer_processes` also binds each declared observer's exact argv and cwd. Only observers with zero publishers and the declared subscription/service ownership are removed from the control graph comparison. Unknown nodes remain subject to the original checks. A declared observer may leave; a changed or restarted instance requires fresh inspection. This compatibility declaration grants no permission to use the user's independent collector during an automatic grasp.

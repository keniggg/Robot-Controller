## 固定 SDK 时有没有持续摆动

每个出向/返回确认停稳后的 3 s 窗口，SDK 指令保持不变。每窗口有约 27–28 组 SDK、accepted 和未经过滤的 raw 关节记录。

- J5 出向、J2 出向及返回、J3 出向：所有关节的 raw/accepted 峰峰值均为 0°。
- J5 返回：只有 J5 变化一个编码刻度 0.087891°，方向为单向；无非零速度方向反转。

因此这几个小幅单轴动作停稳后的观察窗内没有测得持续往复摆动。这不覆盖之前较长、多轴抓取轨迹的整段减速过程，不能证明所有负载与姿态都没有振动。编码分辨率和约 9 Hz 的这批记录也限制了可观察频率与幅值。

## J3 返程未执行的原因

终端为 `reserved path violates 40 mm plane / 20 px board margin`，只发送了一条出向命令，未发送返程或停使能命令。`return_path_decomposition.json` 的离线分解显示：

- 从归档出向姿态到原 SDK 目标的名义返回路径：最小 CAD 平面净距 88.819 mm、板边距 78.680 px，离线几何检查可通过。
- 问题出在把 ±4.8° 的未知实际响应预留区间重新以出向后的姿态为中心；这将正端额外扩展了已走过的 1.669922°。新正端板边距仅 11.993 px，触发 20 px 限制。
- 保留最初绝对角度预留区间的离线正端边距为 35.254 px，最小平面净距约 92.451 mm；但这个旧数据计算不是新运行实例的执行凭据，也不能跳过当前姿态和模型下的重新生成。

这说明本次“返程未执行”有明确的软件包络原因，并非已经观察到机械臂无法返回。新运行实例必须从当前反馈建立新的有效控制参考，不能重放旧 epoch 的返回计划。

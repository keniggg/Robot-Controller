# 固定板局部几何与抓取偏高的恢复设计

本文件是诊断与实现设计，不是已部署的抓取修复。约 10–11 mm 的真实空抓高度偏差尚未关闭；没有修改生产阈值、手眼、目标、轨迹或使能状态。

## 为什么到了预抓取位没有继续补偿

`alicia_grasp_modes/scripts/mode_aware_grasp_task.py:92` 将精确同源 RGB-D 已观测到的支撑正矛盾锁存。`:238` 在原接触计划的物理动作边界返回 `SUPPORT_GEOMETRY_CONTRADICTION`。普通关节补偿只修正“实际 FK 相对于原冻结目标”的到位误差，不能证明原冻结目标在真实桌面上的高度仍正确；原空夹恰好是 FK 已到位而桌面坐标漂了约 10 mm。因此该拒绝不是遗漏补偿。

现有 `final_refine` 也不是独立于 FK 的视觉伺服。`vision/multiview_surface.py:538` 将两帧都表示在 base 下，先要求原始支撑法线及局部平面差不超过现有 4° / 4 mm，再执行绕支撑法线的配准。`grasp_task_node.py:193` 再验证计划的支撑一致性。仅把新云用 ICP 拉回旧模型，会把姿态相关坐标误差隐藏为“已对齐”，不能保证真实指尖高度。仅更新 plan 时间、清 selection 或重选目标，也不能消除已知正矛盾。

## 最小可执行诊断

新增 `.runtime/board_conditioned_geometry_audit.py`：只做纯几何比较，不导入 ROS、不写文件、不返回补偿量或通过结论。对每个同源样本同时计算：

- 机器人链：`P_base = FK(q_accepted) × T_tool_camera × P_camera`。
- 固定板局部链：`P_board = inverse(T_camera_board) × P_camera`。

两帧必须属于同一固定板布置、同一目标、同一 driver epoch、相同相机模型和手眼；RGB、深度、板 TF、quality 来源时间戳严格相等，接收年龄不超过 350 ms，相关 accepted 样本距源图像不超过 100 ms，并由原袋的独立反馈窗口证明停稳。平面用刚体变换的正确逆转置规则变换，并在两帧共享的目标附近锚点比较，不比较远离目标的 d 系数。板坐标内仍有漂移时不会被自动配准消掉。

若 table/object 在板坐标稳定、base 中漂移，则主要矛盾位于 FK 与固定手眼的组合链，而不是物体/桌面真实移动。若板坐标也漂移，深度、PnP、成像模型、板尺度与局部表面观测仍需区分。PnP 与深度共用相机几何假设，不能称为外部真值；即使板坐标稳定，也不单独证明相机至指尖的刚性关系正确。

## 历史实录回放

`.runtime/replay_board_conditioned_geometry.py` 已回放 10:58–11:00 UTC 的新固定板 J5/J2/J3 袋文件。板未跨实验位置比较，每个对照都在本次单关节实验内。结果保存在本次恢复目录 `grasp_repair_resume_20260928T120606Z/board_conditioned_depth_replay.json`。

此回放拟合的是**标定板内部的深度表面**，不是电机或其桌面。每帧先用 SDK 当前射线解投影 Z16 深度，再取板内区域独立拟合深度平面；没有直接把 PnP 板平面当深度平面。使用归档 URDF + accepted 关节重算 FK，且从原袋 `/tf_static` 核验固定手眼。部分辅助 `base_tool` TF 返回 header 存在 1 ns 舍入，故不把这类辅助 header 当同源相机证据；RGB、depth、板 TF 和 quality 的严格源时间配对未放宽。

六帧约 98.6–99.6% 内点；均有原袋验证的前后总计至少 0.8 s 独立停稳窗口。J5/J2 的 `return_post_settle_geometry` 位于录制末尾，没有足够后续反馈组成这次要求的居中窗口，因此明确拒绝，没有用旧值或更短窗口补齐；这不推翻此前采用不同窗口的返回重复性分析。J3 本来没有执行返回。

这组结果与之前小角度实验一致：板局部深度/PnP相对差变化小于 0.4 mm，J2 的机器人链额外产生毫米以下漂移。它不能解释整段抓取的全部 10–11 mm，更不能据此外推线性下移补偿。

## 真正局部闭环的最小集成选择

首先采集覆盖真实预抓取/接近姿态的板、目标与桌面共视数据；同一幅图像提取目标和桌面，板只作为固定参照。保留旧故障记录与原 plan 身份，输出额外的局部几何证据，不能在已知矛盾后悄悄把旧冻结支撑替换掉。

若这些数据在板坐标中保持一致，下一步可采用局部增量视觉伺服：物体接触目标表示为 `T_board_gripper_desired`；当前夹爪位姿为 `inverse(T_camera_board) × T_camera_gripper`。用固定板测得的小幅关节实测响应构造局部 Jacobian，在经过观测覆盖的姿态邻域中求有界增量。Jacobian 的分母必须是 accepted 实际角度变化，不能用 SDK 指令步长；每次增量之后重新观测，误差不收敛或模型域外即不再增加接近动作。

`T_camera_gripper` 不能无条件认作真值：当前可从固定手眼与 CAD 得到估计，但闭爪前还需相机内可见指尖/其他独立几何核对其误差界。否则即使绕过 FK，仍可能保留相机至指尖的固定偏置。若现有视野不能同时看板、目标和足够指尖，当前数据不足以声明局部接触已经验证。

集成应增加明确的局部观测恢复证据类型，而不是修改现有 `register_surface_view` 的 4 mm 限制：

1. `TargetObservation` / `SurfaceView` 另存同源 camera/board 表达、板布置 ID、源时间、模型指纹、原 plan/fault 关联及局部适用域；base 证据继续保留。
2. 任务节点在正矛盾后只能进入该证据的诊断/恢复分支；原计划的普通补偿仍被拒绝。新接触计划必须由新的局部参考完整重建，再检查全部接近路径与 CAD 接触，不沿用旧碰撞结果。
3. 网关从当前 accepted 与实际 SDK hold 重新生成连续关节路径；局部视觉增量必须包含测得响应不确定性。最终闭爪应由新的同源物体/指尖几何独立确认，不能只验 FK 到旧目标。
4. 加入同一局部区间的保留姿态验证：用于估计响应的姿态不能同时充当全部验证姿态。移板、重启 epoch、模型变更、目标换代或越出姿态域后证据失效。

这会涉及 `vision/target_observation.py`、`vision/multiview_surface.py` 的新证据结构，`mode_aware_grasp_task.py` 和 `grasp_task_node.py` 的显式恢复流程，以及 gateway 的新计划完整路径验收；不是加一行 Z 偏置可以安全替代的修复。本轮没有对这些生产路径做未经实录验证的改动。

## 验证界限

纯数学离线回归覆盖：11 mm 姿态相关 FK 偏差只出现在机器人链；真实支撑表面移动仍出现在板坐标；刚体平面有符号距离保持；非同源、旧 epoch、换板/换目标/换模型、未来或超过 350 ms 样本、反向法线与非刚性变换被拒绝。合成验证只证明诊断计算，不代表实机接触成功。

保持用户要求：不移动电机；不固定向下偏置；不放宽既有支撑或运动门限；20 g 是未知物体上限；提升仿真不作硬门，真实提升仍启用；已经修好的近场预抓取时间作用域不改变。抓取关闭条件仍需真实小电机被夹住的证据，而非模型接触通过。

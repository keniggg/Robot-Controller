# 2026-10-03 固定标定板往返验证

## 当前问题范围（按用户最新确认更正）

历史的“夹爪在目标上方闭合、抓取偏高”问题已解决，用户已明确确认。本报告正在诊断的是：初始视角信息不足时，机械臂主动补充观察后，不同视角的观测转换到同一坐标系仍有偏差，影响跨视角信息融合。不能将其写成旧抓取偏高问题尚未解决或已经复发。

当前方案仍以初始视角信息充分时直接抓取为主；信息不足时才补充观察，优先选信息增益足够、姿态和路径合理的视角，必要时继续有限补充，再使用通过一致性核对的多视角信息。当前未解决的是补充视角的坐标对齐与融合一致性，已成功的单视角抓取不因本报告被判定失效。

本轮约 10.6 mm 是固定标定板观测的坐标一致性误差，不是本轮夹爪抓取高度的测量值；本轮没有执行抓取。原“抓取偏高问题仍未解决”的结论表述撤回，下面的测量和诊断证据保留。

本轮自主调姿已完成。跨视角偏差仍未修复，但得到新的独立证据：六轴编码器反馈与记录 TF 都返回相同值后，RGB 观测到的相机—标定板关系没有返回。不能把恢复 SDK 目标或实际反馈等同于相机物理姿态恢复，也不能通过重标一个固定手眼矩阵解释同一反馈对应的两种视觉关系。

原始数据根目录为 SanStand 的 `实验记录/Robot-Controller/ros_log/full_ros_latest_start_20261002/gen4_root_cause/`。本轮完整实验为 `orthogonal_probe_20261003T142728Z`，启动与源码冻结清单为 `board_probe_launcher_20261003T142728Z/startup.json`。所有旧记录保留，未上传或删除。

## 首次 J2 动作后的关系变化

| 对照 | 结果 |
|---|---|
| 动作前两份相同实际姿态 | 板点漂移 RMS 0.118 mm |
| 首次 J2 负向动作 | TF 旋转 2.988°，RGB 旋转约 4.554°，旋转残差约 1.567°，板点漂移 RMS 10.245 mm |
| 首次返回全部原实际反馈 | 相对 baseline 板点漂移约 10.923 mm，旋转关系仍差约 1.599° |
| 整轮最后返回全部原实际反馈 | 相对 baseline 板点漂移仍约 10.630 mm |
| 最后返回后再静止观测 | 板点变化仅约 0.065 mm |

大变化集中在首次 J2 动作，后续返回没有恢复旧视觉关系。首步 RGB 空间留出相对角范围 4.528–4.584°，仍明显不同于 TF 的 2.988°；第二轮 J2 正向实际 3.076°时，RGB 却为 3.047°（留出范围 2.974–3.183°）。它不符合“每转 J2 固定比例产生可逆误差”的简单解释；J5 在首次变化时没有转动，所以 J5 转动不是该变化的必要条件。

本次复现约 10 mm 的持续变化，不将其未经验证地等同于全部历史 19–20 mm 偏差的唯一原因。按真实反馈绘制的[往返对照图](</media/zhuyupei/SanStand/实验记录/Robot-Controller/ros_log/full_ros_latest_start_20261002/gen4_root_cause/orthogonal_probe_20261003T142728Z/return_validation_plot/encoder_return_vs_rgb_drift.png>)及逐点数据保存在 `return_validation_plot/`；橙色圈表示六轴反馈都与基线相同。

同实际姿态的 `T_tool_camera` 完全相同，`T_base_*` 仅有浮点舍入差。首步附近 69 份 SDK 原始反馈与 accepted 的六轴 words 逐份一致；未发现反馈值重写、拒帧、恢复、归零或 TF 切换记录。控制 epoch 全程唯一，反馈 ready 和使能保持，保护未触发。

任何固定的手眼变换都无法让同一组关节反馈同时对应这两个不同的相机—板关系。单轴相对旋转的角度还在固定坐标变换共轭下保持不变。因此不能仅靠替换固定手眼参数消除已观测到的状态依赖现象；RGB 系统误差、场景和机械关系变化仍须分别验证。

比较 baseline 与最终 return_late，排除左侧人手/键盘和完整标定板及其边缘，仅使用板外独立纹理：

- 右上笔记本外壳另有 135 条合格对应，中位位移约 (+3.433, −14.160) px；顶部手机/白盒另有 31 条对应，约 (−2.819, −15.499) px。这些非桌垫物体也有持续向上的像素运动，超出仅“板与整张桌垫一起移动”的解释。动作前和最后返回后的同姿态静止对照中，手机与桌垫中位运动均小于 0.08 px。

## J5 的独立方向相关返回差

目标 word 1559 相同，但两次从较低目标 1525 正向返回时 actual 都为 1550；两次从较高目标 1593 负向返回时 actual 都为 1560。两分支相差 10 words，即 0.87890625°，在后续 J2 动作期间仍保持。最后是负向探测之后正向返回，actual 恢复到初始 1550。

所有最终 SDK 目标均正确；当前 GUI 平滑只根据时间和成功发送词推进，不按反馈残差反复追赶。实际反馈直接解码，没有 host 角度回归。该现象支持执行器/控制器侧方向相关的稳定残差，但不能仅凭编码器记录分清摩擦、死区、齿隙、载荷与内部位置环，也不证明新增 GUI 平滑存在回归。TF 已使用这段实际角度差，不能将它再次当作未计入的固定补偿。

首步还出现三份原始 E1 运行状态，本地 SDK 将其命名为 `overheat`；同期六份温度原始回包为 33–40°C，动作前静止时也存在 E1。没有持续超温证据或保护切换。保留该异常状态，不把它解释为已证实的热故障、温度帧 ID 或此次视觉变化根因。

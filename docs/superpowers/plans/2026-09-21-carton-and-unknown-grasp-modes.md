# Carton 与未知小物体的独立模式方案

日期：2026-09-21。状态：目标类型与执行方式两个维度已实现并接入，测试与实物结果分别记录在会话的 `mode_implementation/` 和各 `attempt` 目录。

用户根据本次运动视频追加要求：面板选择 carton / 未知小物体，再选择一次性 / 两阶段。已通过独立 GUI、remote 与 task 适配落实四种组合，原 carton 源码和配置不改。一次性从当前真实快照生成完整接触计划，两阶段保留原观察位再规划流程；切换同时绑定两个维度，执行中不变更。视频中的约175°转腕发生于观察运动，原有观察搜索比较了部分可行路径时长，不能据此宣称它完全没有路径代价排序。

操作者已选择中心单个物体，并随后明确授权“按照方案修改，完成后自动抓取”。因此本次修改完成后自动尝试，不重复索取“已对准”。原 carton 业务源码、模型、标定和配置保持原样。ROS 已按既有部署启动，不把本方案的开发验证作为启动前置条件。

实现位于最新工作树的 `src/alicia_grasp_modes/`，使用方法见其中 `README.md`。采用独立 ROS 包，以便标准 catkin 构建和 rosrun/roslaunch 使用。2026-09-21 已实际完成 unknown→carton→unknown 往返，收到恢复后的 carton 输出以及 20 组同步 unknown 输出；旧模式计划被拒绝，原运行参数没有改变。初次抓取候选因小目标在原 carton 裁剪中占比约 11.6% 而未通过原 15% 要求，未运动。已新增 unknown 独立的 12 px/0.15 局部裁剪，保留全部最低点数和目标占比要求，继续生成新鲜候选。

## 推荐结构

```text
真实、同步的 RGB-D
  ├─ carton：原 YOLO carton 实例分割入口（保留原实现）
  └─ unknown：独立的桌面分割 + 中心实例选择 + 连续跟踪
                   ↓
        唯一的感知输出选择器（模式、目标代次）
                   ↓
        同帧 ObjectPose + mono8 实例 mask
                   ↓
现有 context_roi → WSL GraspNet → 6D 候选 → MoveIt / MuJoCo
                   ↓
         观察 → 近场更新 → 接近 → 闭爪 → 抬升
```

第一版“未知”指不需要物体类别标签的单个桌面物体。先覆盖可获得有效深度、与邻物分离的物体；透明、反光、过薄、粘连和遮挡目标需要额外方法，不能预先承诺可抓。夹持方向和接触位置由实际点云及候选决定。

## 未知模式的分割与选择

1. 对 RGB 和深度按相机源时间戳配对，保留原始整数纳秒时间和 frame_id；等待同步帧时不复用旧 mask。
2. 使用活动相机内参和 depth_scale 反投影。拟合目标周围的支撑面，检查空间覆盖和拟合残差；不能把屏幕内最大平面无条件当作桌面。
3. 提取高于支撑面的有效深度点并聚类，用真实深度连续性分开不同实例。桌垫的颜色图案不应成为目标。
4. 在画面中心附近选择唯一实例。多个候选相近时报告歧义；没有中心候选时报告不可用，不跳到远处的其他物体。
5. 锁定实例后结合三维位置、mask 重叠和形状保持关联；相机移动后不能每帧重新抢选最靠中心的物体。丢失时清空输出并重建目标代次，旧候选不得执行。
6. 输出完整实例 mask、bbox、中心、深度及几何质量指标；不把几何质量分数描述成语义分类置信度。不能用矩形框代替实例 mask 或用补全模型臆造接触表面。

优先复用已有 `vision/object_geometry.py` 中的平面/点云数学工具，但新增适配层，避免改变 carton 调用的行为。当前中心物体较小且含亮面，第一项开发证据应来自其原始 RGB-D 回放，确认有效点和支撑面能分离。

本次已保存并分析一组源时间戳均为 `1790040471603499174 ns` 的真实 RGB-D。离线复用原平面拟合工具，在中心周围环带拟合支撑面，以 4 mm 高度提取前景，得到中心实例 1240 个有效点、bbox `(302,234,70,23)`、中心距画面中心 14.55 px、深度中位 0.3064 m、离拟合平面的高度中位 6.15 mm。可见表面的 PCA 范围约 46.4×17.6×5.1 mm，这不是完整物体尺寸或可抓性证明。另有少量外围伪前景，说明中心选择和连续一致性仍有必要。

原始数据、纯离线脚本和结果保存在 `.ros_log/ros_live_20260921_session/unknown_sample/`，未发布到公共感知主题、未触发规划或机械臂运动。单帧结果只支持继续开发深度分割路线，尚未证明跨视角跟踪或抓取成功。

## 接口与隔离

以下接口已在独立包 `alicia_grasp_modes` 中实现：

| 部件 | 职责 |
| --- | --- |
| `scripts/unknown_tabletop_perception.py` | 独立未知实例分割、中心选择与跟踪；只发布感知 |
| `scripts/mode_router.py` | carton/unknown 输出选择，管理模式与目标代次、执行占用 |
| `scripts/switch_grasp_mode.py carton\|unknown` | 单一切换入口，显示请求接受或延期状态 |
| `scripts/mode_aware_remote_grasp6d.py` | 复用原 remote，增加代次屏障及 unknown 局部裁剪 |
| `launch/perception_modes.launch` | 只替换感知/规划/任务入口，保留已运行的驱动相机 |
| `launch/full_system_modes.launch` | 用于以后从停止状态启动完整双模式系统 |
| `/grasp_mode/current`、`/grasp_mode/status` | GUI/终端可读的模式状态 |
| `/perception/carton/*`、`/perception/unknown/*` | 分别保存两个感知源的输出 |

公共输出继续兼容 `/perception/object`、`/perception/object_mask`、两个 pose 主题以及 detected/status 主题。mask 为相机尺寸的 mono8 图像，时间戳与对应 RGB-D/ObjectPose 相同。

当前原感知使用 `/perception` 等绝对参数名；仅加 ROS namespace 不会隔离参数。实现时用独立 launch 的逐节点 topic remap 隔离输出，未知配置放入 `/unknown_perception`，原 carton 参数不覆盖。不能让两个节点同时发布公共输出。

下游 `remote_grasp6d_node.py` 的 `_active_profile_requires_mask()` 当前以 YOLO model choice 判断模型切换，并使用 `preserve_identity=True`。这不足以代表 carton/unknown 目标切换：独立适配入口必须显式要求 mask，并让模式变更创建新的目标代次，清除跟踪、多视角表面、缓存及未完成推理的旧结果。执行审计中的模式名称必须真实，不能把 unknown 记录成 carton。

## 切换事务

- 空闲时切换可立即处理；抓取进行中仅记录下一次模式，不在接近、夹持或抬升中更换目标。
- 切换不重启驱动、控制器、相机或 WSL，也不调用 torque-off、disable、下电接口。
- 封住新任务入口，暂停候选请求；等待已在进行的候选退出或标记为过期。
- 向下游发布目标不可用和空 mask；清空旧目标、预览、plan_id、时序缓存和多视角表面。
- 原子提交模式及新代次，只放行切换时间之后的完整同步帧；远端晚到结果必须带代次校验。
- 感知就绪后允许新预览请求，切换不自动启动候选或抓取；本次明确自动抓取授权绑定当前模式、实例和新 plan_id。
- 如果加载失败，报告具体失败阶段，保持目标不可用；不得悄悄切到另一模型并继续执行。切回 carton 使用保留的原参数快照。

## 共同抓取链路的保留与边界

当前输入为 `context_roi`，已有目标 mask、局部支撑面、目标点数和夹爪几何约束。未知模式先复用这些约束。`full_scene` 在原实现中是诊断用途，不能拿来代替实例选择或产生执行计划。

当前配置的夹爪开口为 0.05 m。可夹性按候选接触跨度、手指实体与桌面/邻物净空判断，不等同于“物体任意尺寸小于 5 cm”。未知目标的闭爪力需要作为独立参数设计；不能把 carton 的力参数直接宣称适用于任意易碎物体。

接到“已对准”后，用本轮同步数据生成新预览，再绑定审计与 plan_id 执行一次。只有实际闭爪和抬升反馈支持成功时才记录成功。未产生有效候选、不可达或近场更新失败，均按真实原因报告，不以检测到目标替代抓取成功。

上一轮 `2026-09-20-cross-view-repair-diagnosis.md` 仍记录跨视角几何一致性问题。相机投影修正有离线源码，但默认未启用，独立手眼验证没有通过。模式扩展不修改活动标定、不放宽这些门限，也不把更换感知入口当成该问题已解决。

## 实现顺序与验收证据

1. **保留基线**：记录活动 carton 源文件、模型、参数快照与哈希；新增扩展目录，原文件保持不变。
2. **未知分割回放与旁路预览**：先针对真实中心小物体证明分割有效；独立显示 mask，不争用公共感知主题，不发送运动命令。
3. **切换器及下游适配**：只接管感知与规划入口；用目标代次贯穿帧、候选和执行授权。
4. **切换回归**：验证 carton→unknown→carton、相同位置不同物体、旧结果晚到、模型加载失败、无目标/多目标/深度缺失，以及抓取中切换请求延期。
5. **实际单次抓取**：操作者确认已对准后，执行绑定当前模式的观察、更新、接近、闭爪、抬升流程，并保留结果与关键帧。

这些是新功能开发验证，不是 ROS 启动前的检查程序。当前 ROS、使能和后台监控已经运行。

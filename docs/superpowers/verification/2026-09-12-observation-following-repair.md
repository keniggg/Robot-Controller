## 新确认的软件缺陷：不运动不能证明到位误差为零

旧 `_execute_grasp6d_plan` 在当前观察位可复用时，将 `pregrasp` 设为当前
tool0，跳过观察运动；但随后仍调用通用端点记录函数，把当前位姿与这个
当前位姿相减，覆盖 `/grasp_6d/runtime_execution_error` 为零或很小的静止
漂移。它没有测量成功 SDK 目标与编码器之间的误差，不能证明伺服精度改善。
这是复用路径的独立缺陷；**不是20:28那次确实执行了观察运动的11.98 mm
残差来源**，不能倒置因果。新回归在修改前明确失败：复用分支没有调用独立
跟随证据方法，而错误进入通用端点记录。

修复已接入源码的观察复用分支：

- `stationary_following.py` 只计算证据，不包含 ROS 发布、服务、action 或
  控制接口。使用成功发送的 `/alicia_d/sdk_command`（`sdk_transmitted`）及
  `/alicia_d/accepted_joint_states`（`sdk_measured`），不能用 `/joint_states`
  heartbeat 或上游请求替代。
- 两源需要同一 `/alicia_d/control_reference_epoch` 之后、共同至少0.3秒
  的静止窗口；SDK目标不变，编码器跨度不超过1 count，源龄沿用严格反馈
  合同且不得超过0.5秒。检查关节名/帧、单调源戳、有限值、物理开口和缺样。
  “静止”只描述所采样窗口，不证明窗口之间的连续动态或一次新命令有响应。
- 以未修改 URDF 的同一个 SerialUrdfFk 分别计算 SDK 和实测 tool0。记录明确

  epoch、六轴值和误差计数；近场继续把实测跟随差作为不确定度输入。

270帧源时间1789279018.5098426至1789279048.3089793，SDK269帧到9048.3516896，

### 不可忽略的底层状态，以及当前继续执行的边界

实验结束后在1789278961.105及8962.306出现两次0xE1，后续只读bag又出现两次，
均随后回0。实验期间第8温度通道原始0x42（66°C）相对其余33–38°C突跳，
现有斜率验证将该通道记为NaN；后续又有0x39和0x42。不能只看过滤后max38°C
就宣称没有热问题，也不能凭该不稳定通道断言Joint5真实过热。首次E1晚于
3秒运动完成，尚不能把它唯一归因为本次无响应原因。未调整温度门限、屏蔽
告警或发送失能命令。

驱动在一次34-byte完整成功write后才从该帧解码发布sdk_transmitted，六轴
逐项打包，反馈15-byte载荷按六轴直接解析并整组accepted；本实验数据不支持
“只能一个关节动”或J5目标被上位机遗漏。成功write不等于固件已执行命令，
因此剩余范围是固件接收/内环跟随、死区/换向/负载或真实反馈硬件，尚不能
唯一判为机械损坏。现有ROS没有可验证的伺服增益/死区调参接口。

这不是所有固件都无此能力的证明；需要此设备固件版本与厂家参数/告警说明，
不能猜寄存器、自动升级固件、归零或另开SDK抢占当前串口。

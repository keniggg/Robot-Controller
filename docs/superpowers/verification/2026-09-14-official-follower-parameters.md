## 范围与结论

按用户提供的 ROS1 文档入口，阅读 Follower 下产品介绍、安装使用、ROS1、
Python SDK、ROS2 Humble 的相关内容，并交叉核对系列总览、通信协议和官方源码。
本轮仅查阅网页、源码及历史实验文件、更新记录；没有运行文档例程、连接串口、
调用 ROS 服务、重启节点、运动、归零、切换使能或修改控制参数。
文档中的操作说明不是本轮的执行授权。

公开资料已经提供一部分关键参数，不能笼统说“所有参数都必须等厂家提供”。
但仍未找到适用于本机固件 6.1.3 的小步响应死区、内部控制周期、PID 参数接口
和设备端目标接收确认，故不能仅凭文档认定小步无响应已解决或硬件已经损坏。

## 已找到的参数及适用边界

| 项目 | 官方资料 | 对实验的意义 |
| --- | --- | --- |
| 位置精度 | 系列概述写绝对 ±5 mm，规格表写 ±5～8 mm；重复精度 ±2 mm | 官方两处口径不完全一致，未列负载、姿态、方向和测试方法；不能当作单关节死区，也不能直接拿同模型 FK 跟随差判定实物超规格 |
| 型号与模型 | 版本表：固件 v6.1.x、结构 v5.6.x、SDK v6.1.0；提供 50/100 mm 夹爪 URDF/MJCF | 本机截图固件 6.1.3、夹爪 50 mm，应优先对照 v5.6/50 mm 模型；硬件字段 1.1.0 不等于结构版本 |
| 速度 | ROS1 默认 20 deg/s，范围 4.39～439.45 deg/s；SDK 默认 10 deg/s | 这是接口速度参数，不是所有轨迹的实际平均速度，更不是小步一定响应的保证 |
| 多轴控制 | 六轴可在同一命令设置；ROS1 将 velocity 的最大绝对值换算为各轴公共速度，SDK 也允许速度列表 | 没有“只能一个关节运动”的官方要求；公共速度与各轴独立时间同步不能混为一谈 |
| 软件到位 | SDK set_robot_state 默认 tolerance=0.1 rad、timeout=10 s | 约 5.73° 的逐轴误差容差，显著大于本次 +4 count（0.3515625°）；返回成功不证明小步真实发生 |
| IK 精度 | set_pose 默认 pos_tol=1e-3 m、ori_tol=1e-3 rad | 1 mm /约 0.0573° 是模型求解终止条件，不是实物精度；批量 IK 的默认值另为 1e-2，不能混用 |
| 关节范围 | ROS1 J2 为 −1.57～1.57 rad，J3 为 −0.5～2.356 rad | 本次 J2 约 0.53 rad、J3 约 −0.20 rad 在范围内，不支持“碰到所列角度限位所以小步不动”的解释 |
| 可读状态 | 关节/夹爪、版本、温度、速度、自检、夹爪类型 | 已有可用诊断入口；速度/温度的 10 舵机通道到 6 关节映射仍需明确，不能只按数组下标猜关节 |
| 标定工具 | ROS2 提供 hand_eye_calibration.py、calibration_verifier.py；产品有尺寸图和模型 | 可以继续模型与多姿态标定核对，不等于厂家已提供本机安装后的手眼矩阵或每轴零位误差 |

SDK 源码第 199 行起确认默认 tolerance=0.1；第 830～862 行的等待函数用
所有 abs(actual-target)<=tolerance 判成功。因此，在该默认接口下，足够小的
新目标即使尚未移动也可能已经满足到位判据。这是源码逻辑推论，不是宣称
本次实验调用了这个 Python API。当前 ROS 控制器历史配置的 goal 容差为
0.035 rad（约 2°），与 SDK 默认值不是同一个参数；诊断还另验逐轴响应。
放宽诊断门只能改变“通过”标签，不能使没有响应的关节真正运动。

历史 parameters_before.yaml 中 joint_speed_deg_s=15；此前实码核对量化后
为 150 tick/s，即约 13.1836 deg/s。3 秒内发布 +4 count 的轨迹平均速度
不能与硬件速度字段最低档直接比较，不能据此断言本次命令速度非法。
历史主机命令 50 Hz、保持 10 Hz、状态查询 10 Hz 均不是厂家保证的内环频率。
文档打印 200 FPS、记录 300 Hz、1 ms 缓存读取也不能当作设备实际采样频率。

## 文档中不能直接照搬的内容

1. ROS1 故障排查写 921600 波特率，但当前协议和本轮核对的官方 v6.1.0
   C++ 构造串口都为 1000000。保留已验证的通信设置，不因单处文字改速率。
2. ROS2 一处夹爪开闭方向与 ROS1/SDK/协议相反；后者约定 0 闭合、1000
   全开。任何夹爪执行仍以已核对的实际协议合同为准，不复制矛盾例程。
3. ROS2 eye_to_hand_joint2_offset=-0.04、joint3_offset=-0.06 用于降低
   采样姿态，不是本机编码器零偏补偿，不能加进当前关节反馈或 URDF。
4. ROS2 标定验证中 std_t>2 cm、std_r>2° 是采样稳定性告警线，不是抓取
   允许 20 mm 偏差，更不是替换当前到位/桌面净距门限的依据。
5. 协议中力反馈模式、电流控制等部分限定 Alicia-DL 力反馈示教臂；不能
   因本机是“强力版” Follower 就套用 Leader 专用接口。

## 对历史实验的解释更新

对照 [09-13 部分响应实验](2026-09-13-endpoint-partial-response.md)：J2/J3
同时下发 +4 count，实测 J2 +3、J3 0；动作期及随后 48.730 秒原始回包与
accepted 的逐样本计数序列一致，J3 持续 1909。此前较大动作 J3 曾改变
622 count，故不是“J3 永久不动”的证据。当前有证据的是该姿态/方向下
的小目标未获可测响应；仍需区分固件接收/死区/滤波、负载、摩擦或回差。
主机成功写串口不等于设备目标寄存器确认。

这轮原固定目标 FK 残差 6.411880→5.372112 mm，而新 SDK 目标与实测的
FK 差为 9.242724 mm；前次约 13～15 mm 是其他姿态/测量定义，不能串成
同一个误差曲线，也不能与产品绝对精度指标直接作合格/不合格比较。

模型方面，历史报告确认当前冻结模型的六轴定义与官方旧 ROS1 v5.5 一致。
现在有明确的 v6.1.x→v5.6.x 版本资料，下一步应优先核对新版结构模型、
角度零点/符号约定及 base/tool 变换。坐标系定义不同可能是等价表达，
不能只看 axis/rpy 不同就认定装错模型，更不能未经标定核对直接替换。
模型、手眼、深度误差与关节跟随误差要分别验证，不能用单一偏移全部抵消。

## 尚缺信息与后续工作

公开页面及本轮读取源码中仍未找到：适用于固件 6.1.3 的最小可靠位置增量、
死区/滞回界、内部插补和重复目标处理规则、内环及真实反馈更新周期、设备
目标寄存器/接收 ACK、Follower PID 读写说明与出厂值，以及本机逐轴零偏。
产品写“支持 PID”不能替代可执行协议。以上应定向向厂家询问，不再泛称
“速度、精度、状态接口全都没有”。

可先做的工作：固定官方 ROS1 v6.1.0 和 v5.6/50 mm 模型做离线合同/FK
核对；按正式协议设计同一串口所有者的速度/自检观测；保留逐轴实测到位
判据；随后在授权与原执行边界内设计正反向、不同姿态的有界响应实验，
再用独立外部真值验证模型/手眼/深度，最后验证完整 6D 抓取链。
不更换任务主路线，不限制合法多轴运动，不靠放宽门限制造成功。
本轮没有实施以上控制改动或新实机实验，也不宣称当前节点状态已检查。

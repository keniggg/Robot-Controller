## 修复实现

### A. 在无可达路径时保留有证据的一次注册补拍

新增 `_near_field_unreachable_surface_recovery`。仅当 direct near-field 的
完整 shortlist 非空、全部检查完、没有任何 reachable、结果全部明确为
`MOVEIT_UNREACHABLE`、原截止时间有效，并且当前身份/源戳的成功注册证明
其他方向存在实测表面缺口时，发布 `NEAR_FIELD_SURFACE_VIEW_REQUIRED`。

使用 stream ticket 锁与几何生命周期锁绑定 recovery token。服务错误、过期
注册、错目标、未检查尾部、远端故障、超时和已有成功候选都不能触发该恢复。
原 MoveIt 拒绝仍留在审计；新增 `near_field_recovery` 记录触发原因。
这不是新接触执行权限：任务节点沿用原最多一次、观察距离 18–22cm、真实
CAD/严格路径检查、原绝对 90 秒截止及补拍后 20 秒推理预留。补拍后仍必须
重新识别同一目标、三维配准、生成并完整验证新接触计划；不成功就失败退出。

### B. direct 近场按完整精确序列去重

以 `_dedupe_exact_contact_sequences_for_moveit` 替代该分支的源编号去重。
仅对同一个 prepared 请求、同一目标、上下文、接触中心与开口的 tabletop
候选比较 pregrasp/approach/grasp/lift 全部坐标、四元数、frame 和整数纳秒。
保留确定性 pre-score 最优代表，记录 `contact_sequence_deduplication` 及映射。
不四舍五入、不合并近似方向、不改任一 Pose，不跨请求缓存失败，更不发运动。
GraspNet、far-field 与 legacy 的既有处理不改变。

### 误差产生位置与容忍它的逻辑是两件事

从原watch源时间1789263207.673009的遥测中提取成功SDK写入目标，以唯一最近
SDK count还原量化值（原watch保留7位小数；不是重新解码原始串口帧）：

```
SDK q = [-1.906738119341852, -0.12118448224296566, 0.15339807878856412,
          0.032213596545598466, -0.06442719309119693, 0.2270291566070749]
```

与前述原规划目标q及源戳1789263207109177929的accepted反馈做同模型FK对照：

| 比较 | FK位置距离 |
| --- | ---: |
| 规划关节终点 → SDK量化目标 | 0.181542mm |
| SDK量化目标 → accepted反馈 | 12.798037mm |
| 规划关节终点 → accepted反馈 | 12.958542mm |

最后一项不是原requested Pose的12.921718mm：规划关节解本身与requested Pose
有微小IK残差。距离范数不能直接相加。反馈相对SDK目标的六轴count差分别
为 `[+4, -8, -10, -1, -9, -5]`。主要差异在SDK发送之后的执行/反馈链，不是
上层目标被量化/插值改变了12.9mm。成功写入SDK不等于硬件确认执行目标，
也不能仅据这些记录在内部伺服、负载、回差、编码反馈机制中唯一确定根因。
原终态45.8秒稳定反馈及SDK目标不变，不支持仅靠多等几秒或归咎CPU卡顿。

当前只读参数与源码一致：

- `/alicia_controller/constraints/Joint1..6/goal = 0.035rad`，约2.0°。
  本次最大规划关节终点误差0.015812rad，全部在这个成功范围内。因此
  controller返回SUCCEEDED合理地符合其关节合同，**不代表6mm笛卡尔精度**。
- `observation_endpoint_correction_attempts=0`，普通driver trim关闭；
  `_converge_far_field_observation_endpoint`明确只记录误差、`required=False`。
  `precision_requested`只对CONTACT_EXECUTION_PLAN为真。此次只有观察运动，
  从未进入接触阶段，因而没有启动任务级终点精调。
- 观察阶段按实际18–22cm相机距离及实测CAD净距判断可用，本次210.6mm/7.246mm
  合格；这允许用达到的新视图重建近场，不表示误差已消除或可直接闭爪。
- 接触阶段`measured_endpoint_position_tolerance_m=0.006`、5°保持，必须在
  任务级精调后连续实测通过。12.9mm若出现在接触端点，仍不能继续接近/闭爪。
  本次6mm门限并没有阻止观察阶段微调；该阶段根本没有申请精调。

因此，“安全门限太严格所以12.9mm修不掉”不成立；实际是存在执行/反馈稳态

为防GUI/直控重现自动补偿摆动，也不能简单全局开启driver trim。

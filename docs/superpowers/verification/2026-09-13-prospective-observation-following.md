# 2026-09-13 观察位跟随余量前置修复

## 当前结论与范围

操作者在本轮明确确认前夹指与桌面仍有间隙、没有接触；随后取消了直控。
现场确认不能被写成“已经撞桌”，也不能代替原 3 mm 模型净距要求。
本轮仅修改/测试软件及读取遥测；没有发送运动、失能、归零或控制器
停止/卸载命令。运行部署、回归结论在文末单独追记。

这次失败有两个层次，不能混成“安全门太严格”：

- 执行层：请求 TCP 到实测残差 12.276149 mm，其中 Z 方向低 9.834745 mm。
  同一冻结模型下 SDK—accepted FK 差 12.188265 mm；J2/J3 对总误差
  方向的投影约占 90.5%。控制器 action 的成功不等于末端精确到位。
- 选路/校验层：所选 roll 0°、tilt 15°、20 cm 观察位只检查名义几何，
  再按硬件限速时间排序。SDK 终点左指名义净距 9.721157 mm，accepted
  终点只有 1.797297 mm，损失 7.923860 mm。此前名义连续曲线证明不含
  关节跟随偏差，直到运动结束才被实测 CAD 门拦截。

已证实的选路缺口属于代码逻辑；关节静止残差的物理成因尚未分离固件
死区、静摩擦、负载及舵机控制因素，不能直接宣称硬件损坏或已修复。
本轮前置余量不消除残差本身。固定目标有界校正实验仍未自动接入接触
流程；此前约 15 mm 跨姿态几何问题也未因此取得标定验收。

## 修改内容

1. 候选严格 IK 响应增加精确关节名称/顺序、URDF SHA256；规划期间
   模型或组签名变化就撤销该分支。remote 使用本请求冻结支撑面，对
   对应的实际 IK 关节解做误差盒校验，通过后才参与原时间/关节路程排名。
   不用旧候选 OK、不按固定物体类别改姿态、不扩大原 18–22 cm 距离区间。
2. 余量取运行配置的**运动中**关节容差，至少保留原 0.12 rad，再加 SDK
   半计数 π/4096 rad；不误用较小的 0.035 rad 终点容差，不把配置缺失、
   禁用或非有限值当作零误差。不修改控制器的任何实际容差或温度保护。
3. 各 CAD 角点用 FK 支撑高度雅可比及全局二阶上界包围整个六维关节盒；
   对未决盒有界细分。通过条件是整个盒的高度下界 ≥ 原 3 mm，不是
   检查几个角点/随机采样就宣称安全。每个角点使用自己的半径，避免
   掌部角点过大的半径无故放大所有指尖的估计；超时/预算耗尽仍拒绝。
4. gateway 在最终定时轨迹上把该误差盒叠加到真实 Noetic 多项式区间，
   包含当前 desired 到首个正时间点的桥接段。保留原名义 OBB 检查、
   URDF 限位、连续速度检查；提交前再次核对场景、模型、夹爪开度、
   desired、轨迹 hash、控制权及控制器约束配置。
   六维误差证明单独限于 32768 个盒/25 秒计算预算，预算不足就拒绝；
   原名义路径仍为原默认预算。这是有界计算量调整，不是提高几何/控制
   门限。固定 tool 后缀变换精确合成到每个角点后，才对上游活动关节
   使用全局三角上界，避免把固定工具偏移当成额外可转动连杆。
5. 候选行和连续路径审计分别写入误差范围、模型 hash、条件高度下界或
   数学反例，失败码 `OBSERVATION_FOLLOWING_SUPPORT_INVALID`。数学
   反例不是实机已经发生的碰撞，不把它的负净距写成现场观测。

这是**以给定关节误差范围为前提的夹爪—支撑面几何证明**。控制器
容差不是硬件在故障/停止过程中绝不越界的保证。它不证明手眼/桌面
标定准确，不覆盖全臂环境碰撞，也未扩大目标 OBB 检查至跟随误差盒。
名义目标 OBB 和实测终点检查仍独立保留。不得据此自动放宽接触或证明
持物成功，更不能因一个终点通过就重放旧场景/旧路径。

## 已确定的原因与尚不能确定的原因

- 11.833428 mm 是同一冻结机械模型下，已发送 SDK 目标与独立 accepted
  编码器反馈之间的 FK 差；原目标与实测位置各约 97 秒不变，不是只需再
  等几秒的短时主机延迟。对原 IK 目标的实测误差为 11.791366 mm。
- Joint3、Joint2、Joint5 的误差贡献最大；原 IK 到 SDK 量化目标仅约
  0.196 mm，不能用 SDK 取整解释 11.8 mm。
- 位置控制器现有 0.035 rad 关节容差允许 action 返回成功；这个完成状态
  不是接触前 6 mm / 5° 的实测末端到位证明。放宽接触门限只会接受偏位。
- Noetic 本机 `hardware_interface_adapter.h` 的 PositionJointInterface
  `updateCommand` 直接转发 desired position，未使用 state_error 或 PID
  gains。硬件接口也发布位置命令，因此仅改 YAML gains 不会产生纠偏闭环。
- 尚未分离固件死区/静摩擦/负载跟随/执行保护等因素，不能直接判定关节
  已损坏，也不能声称全部由主机代码造成。约 15 mm 的跨姿态几何问题仍
  要独立尺度或位姿真值，不能靠修改 TF 或此处关节补偿来掩盖。

## 本轮实现：固定物理目标与补偿指令分开

新增 `robot/endpoint_correction.py` 纯计算模块及独立服务
`/supervisor/refine_endpoint_feedback`（沿用 TriggerZero 消息类型，但此
服务不执行归零；只读取 trigger 字段）。`trigger=false` 只规划第一步，
不进行控制器同步，也不代表物理路径已获授权。`trigger=true` 还须私有
参数 `~enable_endpoint_correction_experiments` 明确为 true，默认 false。

1. 冻结实验开始时 SDK 目标为不再改变的诊断目标；补偿后的 SDK 指令是
   独立变量。该目标仍是编码后的参考，不冒充原始 IK 精确目标。
2. 每轴每步最多 4 count，最多 6 步、30 秒、相对最初 SDK 每轴总偏移
   最多 12 count。多轴可同时变化，不引入“只能一个关节动”的限制。
3. 以真实新鲜 SDK/accepted 源戳、相同 epoch/模型及共同静止窗口计算误差。
   只有前一步完成后的独立反馈才能授权下一步：所有被命令轴同向响应
   至少 2 count，响应上界为本步幅度加 2 count；未命令轴漂移不得超过
   2 count。无响应、反向、异常联动均终止本次实验，不继续积分或自动回退。
4. 每步复用严格关节探测的限位、参考连续性、最终定时曲线限速和 CAD
   校验；保留名义 .012 rad 局部范围及 .05 rad 条件跟随误差盒的桌面/
   目标净距校验。最终定时轨迹还必须留足 2 秒反馈预算且满足 ROS/单调
   两个时钟的剩余总预算。预算不能保证硬件故障中的实际动作持续时间。
5. 同时记录相对原始目标的实测误差与 SDK—accepted 跟随差。只以前者
   满足不放宽的 6 mm / 5° 返回诊断收敛，不授予接触或持物成功权限。
6. 执行前把原目标和已消费 epoch 记入 ROS 参数，网关重载也不能在同一
   epoch 再把补偿目标当成新的原始目标继续叠加。无自动重置/重试通道。
7. 失败日志保留最后新鲜测量、已完成步数与提议增量。JSON 中
   `execution_requested` 仅表示请求执行，不能当成轨迹已执行或物理到位。

这是隔离验证所需的小范围闭环，不是重新设计整套 6D 主路线。主流程仍
保持远场观察、近场重建/必要补拍、完整接近、实测到位、双侧触觉闭合与
抬升持物证明。尚不把未经实机证明的积分补偿塞入接触阶段，也未改 driver
现有任务级 precision lease 或全局开启 endpoint trim。

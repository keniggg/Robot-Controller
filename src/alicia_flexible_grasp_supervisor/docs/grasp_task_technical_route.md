## 一、成功证明标准

一次抓取只有同时满足以下证据，才记为成功：

1. 驱动收到正向使能请求后，由新鲜编码器反馈证明执行器确实朝当前命令方向
   运动，而不是仅证明串口写出了使能帧。
2. 抓取任务绑定一份新鲜、可审计的目标快照和唯一计划 ID。
3. 第一阶段观察运动和允许的一次径向修正均有命令、控制器结果及实测终点证据。
4. 第二阶段使用到达近场后采集的单次融合 RGB-D 快照重新确定目标和候选，
   并在有界比较中冻结通过全部硬门控及完整严格 MoveIt 检查的候选。
5. 接触执行严格绑定该候选的预抓取、直线接近、抓取、闭合和抬升位姿，
   中途没有候选漂移、旧计划重放或越权替换。
6. 各运动阶段均有新鲜编码器变化、实测终点误差和控制器结果；夹爪闭合命令
   与抬升结果可追溯。
7. 目标被闭合夹爪带离支撑面并保持到抬升终点，任务状态发布成功，且审计记录
   能把本次执行唯一地关联到快照、候选、计划和实测反馈。

仅有以下任一现象都不能证明抓取成功：写出正向使能帧、发布运动命令、
MoveIt 找到路径、MuJoCo 仿真通过、控制器返回成功但编码器不动，或夹爪闭合
而目标没有随抬升离开支撑面。

## 二、权限与数据链

### 2.1 执行权限

- 操作者拥有上电、断电、冷却判断、拖动示教和失能/停止权限。
- 软件启动、串口重连和 `/demonstration=false` 只允许发送既有的正向
  torque-on 帧。
- 软件不得因超时、过热、规划失败或执行未确认而自动发送 torque-off、
  `/grasp/stop`、控制器停止、失能或急停命令。
- 自动抓取只有在驱动发布新鲜的实测执行确认后才能取得运动权限。

### 2.2 感知与规划权限

- 相机节点提供同步的彩色、深度和相机标定数据。
- 远端 6D 节点负责形成融合目标快照、候选硬门控、确定性排序和严格 MoveIt
  序列检查。
- 抓取任务节点只执行带唯一计划 ID 的冻结计划，不得在接触阶段自行换候选。
- MuJoCo 保留为离线审计和显式 legacy 策略工具；在生产
  `single_snapshot_direct` 近场路线中不拥有执行否决权。

### 2.3 反馈权限

- `/joint_states` 的新鲜编码器反馈是机械臂是否实际响应的权威证据。
- 控制器 action 结果必须与编码器变化和实测终点联合判断，不能单独作为成功
  证明。
- `/alicia_d/motion_enabled` 只表示已由实测运动确认，不再表示“正向使能帧
  已写出”。
- `/alicia_d/actuation_status` 保存 `DISABLED`、`PENDING`、
  `CONFIRMED`、`UNCONFIRMED` 或 `OVERHEAT_BLOCKED` 及原因。

### 2.4 手眼标定前置证据

- 自动抓取只能加载已完成独立多姿态不变性验证的 `tool0 -> camera_link`
  外参；旧外参、仅成功求解但未验证的外参以及标定板检测失败时的结果均不能
  解除标定互锁。
- 当前 `CC200-15-1125` 板按实时码字和几何证据使用 `12×9` 方格、
  `15 mm` 方格边长、`11.25 mm` marker 边长和 `DICT_5X5_100`。板厚
  `3.2 mm` 只描述基板，不加入印刷标定平面的方格或 marker 尺寸。
- D405 的 640×480 标定流允许只在码检测内部放大 `2×`；所有检测角点必须在
  PnP、重投影、边界余量和绘制之前严格还原到原始像素坐标，相机内参不得随之
  缩放或替换。
- 放大检测使用上一帧真实 marker 外接框加原图像素余量形成动态 ROI，并复用
  同一次 marker 搜索做 ChArUco 插值；ROI 失配时必须立即回退完整原图重新
  获取，不能把缓存 ROI、角点或姿态当作当前帧证据。
- 每个求解样本必须有新鲜姿态、至少 `35` 个 ChArUco 角点、至少 `12 px`
  原图边界余量和不高于 `1.5 px` 的原图重投影 RMS，并通过短时间稳定窗口。
- 求解后先在同一批样本上并行审计 OpenCV 的 Tsai-Lenz、Park、Horaud、
  Andreff 和 Daniilidis 五种算法，并执行确定性五折交叉验证；每个样本必须
  恰好作为一次留出样本，不能只用全量样本内残差挑选外参。
- 只有交叉验证同时满足平移 RMS/最大值不高于 `3/5 mm`、旋转 RMS/最大值
  不高于 `1/2°`，候选才有资格进入独立验证。交叉验证失败时不保存、不发布
  候选外参，也不通过删除离群样本或切换算法绕过验证。
- 求解样本与最终验证样本必须分离；最终至少使用六个未参与求解的不同姿态，
  要求平移 RMS/最大值不高于 `3/5 mm`，旋转 RMS/最大值不高于 `1/2°`。

## 三、端到端技术路线

### 3.1 上电后的执行确认

1. 启动或串口重连时清除旧的 SDK 插值目标和旧执行证据。
2. 发送一次既有正向 torque-on 帧，将状态置为 `PENDING`；不伪造固件确认。
3. 等待第一份新鲜真实关节反馈。反馈到达前收到的关节命令不保留、不重放。
4. GUI“同步当前关节”或等效同步命令必须发送当前实测关节的零运动基线，且该
   基线必须处于当前反馈的配置容差内，才解除重连命令互锁；最小手眼面板在
   第一条 jog 前若仍处于重连/未确认状态，也必须先发布同一零运动基线。
5. 操作者执行一个超过探测阈值的小幅 GUI 运动。
6. 在确认时限内，至少一个被命令关节必须产生超过可测阈值且方向与命令一致的
   新鲜编码器变化，状态才转为 `CONFIRMED`。
7. 零变化、反向变化或无关关节跳变均不能确认；超时转为 `UNCONFIRMED`。
8. `0xE1`/`0xE2` 与同一有效温度通道持续达到既有上限同时出现时，转为
   `OVERHEAT_BLOCKED`，等待冷却和物理上电恢复，不自动失能。
9. 温度响应中高于 `125 C` 语义可信上限的单个通道记为无效值，不能参与连续
   过温计数；同一响应内其余有效通道仍独立按原 `60 C`、连续三次规则判断，
   不能因一个坏通道而掩盖真实过温。`125 C` 只用于协议语义校验，不替代或
   放宽原过温阈值。
10. 任何被关节连续性或实际下发命令一致性拒绝的编码器帧，都不得刷新真实
    反馈时间、发布 `/joint_states` 或驱动末端精调。实际成功下发的最后位置在
    命令流暂停后仍作为突变一致性参考；只有物理速度包络内的连续实测变化或
    重连后的新初始状态可以建立新的反馈基线。
11. 6D 任务失败只释放任务执行权限，不自动改变力矩状态。GUI 关节直控在
    操作者实际移动滑条后读取驱动执行状态；若为 `DISABLED`、`UNCONFIRMED`
    或 `OVERHEAT_BLOCKED`，只发送一次既有的 `/demonstration=false` 正向使能
    请求，并只暂存本次 GUI 目标。必须在请求之后收到一份新的真实关节反馈，
    先发布与该实测姿态完全相同的零运动同步目标；只有驱动返回
    `COMMAND_SYNCHRONIZED`（或已有更新的实测执行确认），才把原 GUI 目标发布
    一次并继续按方向编码器响应确认。这样首次滑条位移不受重连同步容差限制，
    同时又不能用旧控制器目标建立同步。后台计时器不重复使能，旧任务目标不
    重放；使能被当前过温证据拒绝或握手超时时丢弃暂存目标，要求操作者再次移动
    滑条。该恢复路径不发送 `/demonstration=true`、停止、失能、torque-off、
    抓取重试或控制器目标重放。
12. GUI 直控命令必须在 `header.frame_id` 中标记 `gui_direct`，并在 `effort`
    字段携带恰好一个 one-hot 编辑通道；零运动同步单独标记为
    `gui_direct_sync`。驱动不信任 GUI 同时携带的其余滑条值：每段新手势优先继承
    最近一次成功写入硬件的 SDK 关节设定值作为未编辑轴保持基线，只在尚无新鲜
    SDK 设定值时回退到编码器反馈，并只替换被标记通道。这里不能无条件用反馈值：
    位置伺服可在稳定时保留小幅命令—反馈偏差，把反馈值重新写成设定值本身就会
    让未编辑轴产生新目标。同一手势 `0.25 s` 窗口内拒绝其他
    `/joint_commands` 源插入。每条直控/同步命令同时清除任务端点租约与反馈精调
    偏移，防止任务结束后把 Joint2/3/5 的历史修正叠加到手动目标。
13. `/gui/joint_direct_mode` 的锁存主题与持久参数共同表达操作者控制权；勾选
    期间驱动持续只接受 GUI 直控/同步来源，任务和网关拒绝自动动作，保护不因
    单次手势结束而到期。取消勾选后拒绝旧滑条命令，滑条按实测反馈实时更新，
    显示刷新不得触发运动发布。
14. 自动命令参考连续性修复（2026-09-12已加载，实机流程待验）：真正没有成功SDK命令的初始
    正向使能周期才用新鲜六轴反馈建立原 `0.003 rad` 内的初始基线；有成功
    命令的手动交权须保持冻结SDK位置字，不把残差actual重写成新目标。
    已完成自动阶段只保留可追溯的controller desired，零保持重发；下条轨迹
    必须证明真实desired接续段的名义速度与适用几何，不能凭单帧零速度冒充
    完成。初始化同值命令被硬件省略时，仅允许专用同参考准入，接收端再验
    epoch/命令字并要求新成功写入遥测；不得靠微动、放宽ACK或夹爪补值解锁。
    新鲜观察计划仍可通过严格路径开头每轴最多 `0.025 rad` 的有界片段取得
    真实运动确认；无响应不自动重复尝试。多轴同时运动与多自动阶段保持允许。
15. `CONFIRMED` 后仍监测连续命令流的实际同方向响应；响应丢失或确认超时
    转为 `UNCONFIRMED`，旧目标 keepalive 和迟到反馈不能重新触发确认。
    必须由新的显式正向使能握手建立新证据，不能用历史确认遮盖当前无响应。

### 3.2 第一阶段：远场观察

1. 从当前相机数据生成新鲜远场候选并绑定目标 epoch、快照和计划 ID。
2. 对目标几何、支撑面、有限数值、夹爪模型、碰撞、关节限位和目标新鲜度执行
   硬门控。
3. 严格规划并执行相机观察位姿。
4. 用编码器和相机重新测量已到达终点及相机到目标距离。
5. 只有在距离落在既有闭区间契约外时，允许现有的一次实测径向修正。
6. 观察位或径向修正的严格轨迹提交后，如果控制器返回失败，不凭总关节增量
   接近计划值而判成功，也不放宽关节终点容差。先保留反馈证据、等待运动稳定，
   再使用一份新鲜相机观测重新计算相机到同一目标的距离。
7. 只有新鲜实测距离进入原有观察闭区间，才把这类控制器判负视为“观察合同
   已由实际结果满足”并继续；距离仍越界、目标丢失、目标实例变化、反馈未稳定
   或观测超时都精确失败。
8. 该相机距离恢复权限只适用于接触前的远场观察位和最多一次径向修正。近场
   预抓取、接近、抓取及抬升不得复用观察合同；它们只允许按 3.4 节由同一
   冻结位姿的实测端点合同裁决已经提交的接触轨迹。
9. 修正后满足观察区间才进入第二阶段，否则精确失败。
10. 观察运动使用独立严格规划实例、缓存与速度配置；观察预抓取、径向修正和
    初始近场补拍按已冻结的观察计划选择该配置。接触计划继续使用独立的接触
    限速，观察提速不改变路径、加速度约束、控制器容差及实测端点合同。
11. 复用当前观察位没有新执行端点，不能用当前位置自比较来证明执行误差为零。
    此时独立采集同一控制参考epoch内的成功SDK/accepted静止窗口，以同模型FK
    跟随差提供近场不确定度；明确与执行端点分开，不作为径向修正前馈或标定
    合格证据。数据缺失、不新鲜或不静止时失败，不以0代替未知。当前净距、
    相机距离、目标关联和后续完整接触门控依然独立执行。
12. 观察候选先对严格 IK 的具名关节解执行支撑面跟随余量校验，再按原硬件
    限速时间和关节路程选择。余量使用运动中而非终点关节容差，配置缺失不
    默认为零。最终定时曲线及 desired 桥接段再次校验同一条件误差范围内
    的夹爪支撑净距；原 3 mm、名义目标 OBB、关节限位及实测端点门不变。
    条件支撑面校验不代表硬件跟随/停机保证或标定合格，不授予近场接触权限。
13. 同一已提交计划的外层ROS消息序号随重发递增不构成场景变化。计划上下文
    摘要仅排除该传输字段；源戳、坐标系、目标、几何及位姿的真实冲突仍拒绝，
    轨迹原始字节hash不受影响。新场景不替代已经结束任务的运动权限。

### 3.3 第二阶段：单次近场视觉修正

生产策略固定为 `near_field_strategy: single_snapshot_direct`：

1. 到达远场观察位并取得新鲜同标签观测后，任务节点一次性发布带阶段 ID、阶段
   起点、绝对截止时间和“到达观察位后的实体中心”的近场阶段合同，并废弃远场
   候选 epoch。实体中心由当前视觉表面点相对远场计划支撑面中心的实测修正得到；
   原始图像源时间必须不早于到达观察位的时间门。该合同是任务、远端选择与
   MoveIt 检查共用的唯一时间及中心参考权威。
2. 使用近场专用的三个互异同步 RGB-D/掩码/目标样本，只形成一次当前融合点云
   和目标快照；远场观察规划仍使用五帧，不复用远场帧充当近场证据。
3. 在冻结快照上重新生成候选。近场接触使用当前实测注册点云的尺寸、朝向、
   支撑面、中心及法向；连续性由同目标 `VALID_3D` 配准的内点/视图数量、
   重叠率、RMSE、位姿修正及支撑面一致性共同验证。检测框表面点减半高得到的
   中心代理不能替代注册中心，也不能强行平移点云。旧的非接触计划仍使用原
   平面中心合同；缺失或不足的三维证据不能回退到中心代理获得接触权限。
   近场 GraspNet 返回集限为 `12`，保留有界 learned
   提议集作为补充；独立的本地
   桌面几何候选仍完整保留最多 `32` 个；两类候选都必须重新执行几何、支撑
   间隙、夹爪 CAD、有限数值、碰撞、关节限位、目标漂移和新鲜度门控。
4. 对当前硬安全候选执行确定性权威排序。
   同请求、同目标、几何上下文、接触中心和开口下，仅合并四阶段坐标、
   四元数、frame及整数源纳秒完全相同的桌面序列；不按源编号误合并，
   不合并相近姿态或不同夹爪方向，去重映射写入审计。
5. 按排序逐个进行完整接触序列的严格 MoveIt 检查。
6. 首个完整严格可达候选成为保留方案，随后至多使用原 `8 s` 有界比较预算，
   同时保留 `2 s` 发布余量；以开口余量为先，比较已验证完整路径的硬件限速
   时间下界、最大关节位移和路径代价。不会等待跨请求稳定命中，也不宣称
   全局最优；后续失败不能消耗掉已有有效方案。
7. 整个近场阶段预算为 `90.0 s`，包含开启推理、初始注册快照、远端候选处理、
   严格 MoveIt 检查，以及符合下述条件时的一次观察补拍与第二次新快照；
   绝对截止时间在入口固定，补拍或后续快照不能重新续期。
8. 阶段绝对截止时间必须随严格序列和自由空间姿态解析请求下传。每个候选、
   序列阶段和确定性 IK 样本开始前都复核剩余时间；到期后停止启动新检查，
   未检查尾部明确记为未检查，不能记为不可达。
9. 有界比较结束后发布并冻结所选精确接触执行预览及计划 ID。若形成精确
   失败终态，远端发布绑定当前阶段窗口的新鲜无效 Preview，任务节点立即结束
   等待；无效 Preview 永远不能取得执行权限。
10. 有效计划或精确失败终态提交后，关闭本次连续候选推理。

初始近场仅因可容纳方向缺少实测双侧接触表面/接触高度而失败，且身份、时间戳
及三维注册有效时，允许从冻结观察计划进行一次有界注册补拍。其他方向的碰撞
失败不应掩盖该缺失表面诊断。完整非空候选集全部检查完且均明确运动学不可达
时，也须保留其他可容纳方向的这类实测表面缺口；有几何合格接触点不等于有
完整可达路径。服务错误、错目标/过期注册、未检查尾部、远端故障或预算耗尽
不能触发该分支，已有完整可达方案不额外补拍。缺表面诊断不成为抓取候选，
也不证明该方向已运动学可达。补拍使用既有双方向
严格规划与真实夹爪/相机包络约束，保持观察距离合同，使用预留范围内的外侧
半径。执行前须为轨迹、稳定等待和 `20 s` 新推理预留总时间；完成后只使用
新阶段实测视角，配准失败不能补造背面或获得接触权限。

目标位置与平面朝向由现场观测决定，系统应在原位置寻找符合实测几何和完整
路径合同的分支。有限候选失败只说明本次候选集未成功，不证明整个位置不可抓取。
不得把移动目标物、固定摆放或虚拟坐标偏移作为泛化抓取的前提。

这一次融合近场快照是候选姿态的主要“重新看图像并修正”。生产直抓路线不增加
远端 MuJoCo 候选筛选或任务节点重复仿真；但候选预抓取到达后、直线接近开始前，
还必须执行一次轻量有界最终视觉精修，用来消除观察位采样与近场候选冻结之间的
残余平移，而不是重新选择任意候选。

### 3.4 接触与抬升

冻结近场计划后，按以下固定顺序执行：

1. 若候选预抓取位姿不同于已到达观察位姿，执行候选专属预抓取运动；
2. 请求同一目标轨迹及候选谱系的新鲜三维注册 Preview；检测框中心不能产生
   执行位移，原始中心 fallback 关闭。按实测重叠、内点、残差、修正及支撑面
   合同验证有限刚体修正，并对更新后的完整接触序列重新做严格 MoveIt 检查。
   裁切图像的有效内部深度可用于注册，裁切中心不可用于重定位；证据不足时
   仅允许既有的一次合规补拍。精修等待预算为 `20 s`；移动后的确认另按
   `12 s`、五个新鲜三维注册 Preview、`6 mm` 残差合同执行，不沿用旧中心；
3. 执行严格直线接近；
4. 执行严格直线抓取位姿；
5. 无触觉模式先从冻结 6D 计划的 `required_open_width_m` 扣除规划阶段为进场
   保留的两侧 jaw clearance，再减去配置预载，发送计划绑定闭合位置；不能把
   进场余量当成物体实体宽度。非 6D 路径仍使用独立配置的固定闭合位置；
6. 执行严格直线抬升。

近场接触计划完成最终视觉精修并再次冻结后，后续直线接近和抓取运动中夹爪或腕部
遮住目标属于预期现象。该阶段的目标丢失、过期或低置信观测保留同一冻结计划，
不能把它墓碑化，也不要求机械臂为了重新看见目标而暂停已经通过门控的接近序列。
检测仍为真但边界框进入相机边缘余量的部分掩码同样只按遮挡处理：它不能驱动
重定位，也不能用残缺质心触发目标漂移撤权。该规则只对已经显式允许近距遮挡的
冻结接触计划生效。冻结前、边界完整的新鲜观测、实例变化、空或非法边界框仍按
原目标漂移和实例一致性硬门失败。非视觉遮挡类的计划完整性、执行确认、碰撞和
显式停止事件始终保持原硬撤权语义。

每一步开始前重新验证执行确认新鲜度、计划 ID、目标新鲜度/漂移、当前关节
状态和阶段权限；每一步结束后联合验证控制器结果沿革、编码器变化及实测终点。
规划失败、计划校验失败、控制器不可用或缓存轨迹尚未提交均立即失败。只有返回
信息明确表明缓存的严格/笛卡尔接触轨迹已经提交时，控制器判负才可进入下述
同端点实测裁决；它本身既不算成功，也不直接授权下一段。任一门控失败都停止
进入下一接触阶段，但不自动发送 torque-off 或失能命令。

近场候选的关节运动幅度只参与姿态优选，不构成新的硬错误条件。候选通过全部
硬几何和碰撞门控后，使用同一冻结图像/TF 快照计算当前工具姿态到候选预抓取
姿态的旋转变化和位移，按旋转、位移、原几何软分数及稳定 ID 的确定顺序接受
严格 MoveIt 检查。包括腕部约 180° 旋转在内，只要完整序列满足既有旋转扫掠、
关节限位、碰撞和严格 MoveIt 门控，就仍可执行；较短姿态只是先检查，不得以
软排序替代“能否抓取”的几何与运动学证明。

控制器 action 成功也不单独证明接触位已精确到达。对
`CONTACT_EXECUTION_PLAN` 的预抓取、接近、抓取和抬升，每一段在轨迹控制器
完成并保持同一目标后，由任务节点取得驱动的限时端点精度租约。驱动只在目标
和编码器均稳定、误差处于
既有有界窗口且高于两倍 SDK 量化步长时，按所有关节同一规则累计实时反馈补偿；
租约释放后只保持当前未变化目标的已测补偿，下一条不同目标自动清零。普通
GUI/手动命令的全局端点微调始终关闭，租约另有 `120 s` 自动过期保护。

控制器返回后，无论 action 成功，还是已提交缓存接触轨迹后判负，任务都继续
使用同一冻结计划位姿取得端点精度租约，等待连续实测
`base_link -> tool0` 样本满足原 `6 mm / 5°` 合同，并再记录一次当前样本。
只有两者都通过才进入下一接触动作；超时或当前样本越界均失败闭锁。该闭环不
重新规划、不重试轨迹、不重新看另一目标、不改变计划位姿、不放宽控制器或
笛卡尔门限，也不发送 stop、失能或 torque-off。

### 3.5 终态和审计

- 成功：发布唯一成功终态，并保存快照 ID、候选来源、确定性排序、严格规划
  结果、冻结计划 ID、每段目标/实测关节值、端点误差、夹爪命令和抬升结果。
- 失败：发布最精确的有界原因，释放本次任务执行权限，不把未检查候选标成
  不可达，也不把请求写出标成硬件响应。
- ROS 节点在成功或失败后保持在线，方便继续观察；终态处理不包含自动停止、
  失能或 torque-off。

## 四、不可放宽的硬门控

无论采用哪次路线优化，以下检查不得为了提高成功率而跳过：

- 相机内参、深度、TF 和时间戳有效性；
- 目标点云、包围盒、支撑面和抓取几何有限性；
- 手指、掌部、支撑面及环境碰撞；
- 完整旋转扫掠、关节限位和严格 MoveIt 规划；
- 当前关节状态、目标快照、目标漂移和计划 ID 新鲜度；
- 接触序列各阶段的端点一致性、控制器结果沿革及缓存轨迹提交证据；
- 正向使能后的实测执行确认。

路线优化只能删除重复权威、重复计算和没有新增证据的等待，不能删除上述硬
安全与一致性证明。

控制器 action 判负有两项互不复用的边界裁决：接触前观察运动只能由新鲜实测
相机—同一目标距离满足既有观察合同；接触计划只能在缓存严格/笛卡尔轨迹已经
提交后，由同一冻结位姿的连续实测端点合同满足。任何提交前失败、合同超时或
最终当前样本越界仍然失败；两项裁决都不是关节终点容差放宽。

## 六、验证路线

### 6.1 离线验证

1. 先写可复现旧故障的失败测试，再实现最小修复。
2. 分别验证驱动状态机、重连命令准入、GUI 单通道 one-hot 意图、直控反馈基线
   锁存、任务执行门控、到达观察位中心合同、近场单快照选择、严格 MoveIt
   首可达停止、无 MuJoCo/重复仿真，以及接近前有界 final-refine 调用。
3. 运行受影响套件、完整相关测试、Python 编译、YAML/XML 解析、
   `git diff --check` 和 catkin 构建。
4. 离线验证不得启动 ROS 硬件接口或发送硬件命令。

### 6.2 真机验证

1. 操作者确认机械臂已冷却并上电。
2. 启动完整 ROS 节点，只发送正向 torque-on；驱动应先报告 `PENDING`。
3. 操作者点击“同步当前关节”；最小手眼面板会向驱动发送当前位置零运动基线，
   避免 `Step deg` 大于重连同步容差时第一条 jog 被判为旧命令。然后再用 GUI
   做一个小幅动作。
4. 只有编码器方向一致的实测变化使状态变为 `CONFIRMED` 后，才允许自动抓取。
5. 操作者对准目标，系统生成一份新鲜远场计划并执行第一阶段观察。

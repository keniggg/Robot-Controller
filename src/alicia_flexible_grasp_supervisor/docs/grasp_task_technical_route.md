## 一、成功证明标准

一次抓取只有同时满足以下证据，才记为成功：

1. 驱动收到正向使能请求后，由新鲜编码器反馈证明执行器确实朝当前命令方向
   运动，而不是仅证明串口写出了使能帧。
2. 抓取任务绑定一份新鲜、可审计的目标快照和唯一计划 ID。
3. 第一阶段观察运动和允许的一次径向修正均有命令、控制器结果及实测终点证据。
4. 第二阶段使用到达近场后采集的单次融合 RGB-D 快照重新确定目标和候选，
   并冻结第一个通过全部硬门控及严格 MoveIt 检查的候选。
5. 接触执行严格绑定该候选的预抓取、直线接近、抓取、闭合和抬升位姿，
   中途没有候选漂移、旧计划重放或越权替换。
6. 各运动阶段均有新鲜编码器变化、实测终点误差和控制器结果；夹爪闭合命令
   与抬升结果可追溯。
7. 目标被闭合夹爪带离支撑面并保持到抬升终点，任务状态发布成功，且审计记录
   能把本次执行唯一地关联到快照、候选、计划和实测反馈。

仅有以下任一现象都不能证明抓取成功：写出正向使能帧、发布运动命令、
MoveIt 找到路径、MuJoCo 仿真通过、控制器返回成功但编码器不动，或夹爪闭合
而目标没有随抬升离开支撑面。

## 二、权限与数据链

### 2.1 执行权限

- 操作者拥有上电、断电、冷却判断、拖动示教和失能/停止权限。
- 软件启动、串口重连和 `/demonstration=false` 只允许发送既有的正向
  torque-on 帧。
- 软件不得因超时、过热、规划失败或执行未确认而自动发送 torque-off、
  `/grasp/stop`、控制器停止、失能或急停命令。
- 自动抓取只有在驱动发布新鲜的实测执行确认后才能取得运动权限。

### 2.2 感知与规划权限

- 相机节点提供同步的彩色、深度和相机标定数据。
- 远端 6D 节点负责形成融合目标快照、候选硬门控、确定性排序和严格 MoveIt
  序列检查。
- 抓取任务节点只执行带唯一计划 ID 的冻结计划，不得在接触阶段自行换候选。
- MuJoCo 保留为离线审计和显式 legacy 策略工具；在生产
  `single_snapshot_direct` 近场路线中不拥有执行否决权。

### 2.3 反馈权限

- `/joint_states` 的新鲜编码器反馈是机械臂是否实际响应的权威证据。
- 控制器 action 结果必须与编码器变化和实测终点联合判断，不能单独作为成功
  证明。
- `/alicia_d/motion_enabled` 只表示已由实测运动确认，不再表示“正向使能帧
  已写出”。
- `/alicia_d/actuation_status` 保存 `DISABLED`、`PENDING`、
  `CONFIRMED`、`UNCONFIRMED` 或 `OVERHEAT_BLOCKED` 及原因。

## 三、端到端技术路线

### 3.1 上电后的执行确认

1. 启动或串口重连时清除旧的 SDK 插值目标和旧执行证据。
2. 发送一次既有正向 torque-on 帧，将状态置为 `PENDING`；不伪造固件确认。
3. 等待第一份新鲜真实关节反馈。反馈到达前收到的关节命令不保留、不重放。
4. GUI“同步当前关节”或等效同步命令必须处于当前反馈的配置容差内，才解除
   重连命令互锁。
5. 操作者执行一个超过探测阈值的小幅 GUI 运动。
6. 在确认时限内，至少一个被命令关节必须产生超过可测阈值且方向与命令一致的
   新鲜编码器变化，状态才转为 `CONFIRMED`。
7. 零变化、反向变化或无关关节跳变均不能确认；超时转为 `UNCONFIRMED`。
8. `0xE1`/`0xE2` 与同一有效温度通道持续达到既有上限同时出现时，转为
   `OVERHEAT_BLOCKED`，等待冷却和物理上电恢复，不自动失能。

### 3.2 第一阶段：远场观察

1. 从当前相机数据生成新鲜远场候选并绑定目标 epoch、快照和计划 ID。
2. 对目标几何、支撑面、有限数值、夹爪模型、碰撞、关节限位和目标新鲜度执行
   硬门控。
3. 严格规划并执行相机观察位姿。
4. 用编码器和相机重新测量已到达终点及相机到目标距离。
5. 只有在距离落在既有闭区间契约外时，允许现有的一次实测径向修正。
6. 观察位或径向修正的严格轨迹提交后，如果控制器返回失败，不凭总关节增量
   接近计划值而判成功，也不放宽关节终点容差。先保留反馈证据、等待运动稳定，
   再使用一份新鲜相机观测重新计算相机到同一目标的距离。
7. 只有新鲜实测距离进入原有观察闭区间，才把这类控制器判负视为“观察合同
   已由实际结果满足”并继续；距离仍越界、目标丢失、目标实例变化、反馈未稳定
   或观测超时都精确失败。
8. 该恢复权限只适用于接触前的远场观察位和最多一次径向修正。近场预抓取、
   接近、抓取、闭合及抬升仍要求原有控制器和实测终点门控，不得复用观察合同
   绕过接触运动失败。
9. 修正后满足观察区间才进入第二阶段，否则精确失败。

### 3.3 第二阶段：单次近场视觉修正

生产策略固定为 `near_field_strategy: single_snapshot_direct`：

1. 进入近场时由任务节点一次性发布带阶段 ID、阶段起点和绝对截止时间的近场
   阶段合同，并废弃远场候选 epoch。该合同是任务、远端选择与 MoveIt 检查
   共用的唯一 `30.0 s` 时间权威。
2. 使用配置的多帧窗口，只形成一次当前融合 RGB-D、掩码、点云和目标快照。
3. 在冻结快照上重新生成候选，并重新执行几何、支撑间隙、夹爪 CAD、有限数值、
   碰撞、关节限位、目标漂移和新鲜度门控。
4. 对当前硬安全候选执行确定性权威排序。
5. 按排序逐个进行完整接触序列的严格 MoveIt 检查。
6. 第一个严格可达候选立即胜出；不继续穷举，不等待跨请求稳定命中。
7. 整个近场快照与选择阶段预算为 `30.0 s`，包含开启推理、形成融合快照、
   远端候选处理及严格 MoveIt 检查；不得从较晚的融合快照重新启动另一段
   30 秒。
8. 阶段绝对截止时间必须随严格序列和自由空间姿态解析请求下传。每个候选、
   序列阶段和确定性 IK 样本开始前都复核剩余时间；到期后停止启动新检查，
   未检查尾部明确记为未检查，不能记为不可达。
9. 第一个严格可达候选立即发布并冻结精确接触执行预览及计划 ID。若形成精确
   失败终态，远端发布绑定当前阶段窗口的新鲜无效 Preview，任务节点立即结束
   等待；无效 Preview 永远不能取得执行权限。
10. 有效计划或精确失败终态提交后，关闭本次连续候选推理。

这一次融合近场快照就是“重新看图像并修正”。生产直抓路线不再增加远端
MuJoCo 候选筛选、任务节点重复仿真或第二次 final visual refine。

### 3.4 接触与抬升

冻结近场计划后，按以下固定顺序执行：

1. 若候选预抓取位姿不同于已到达观察位姿，执行候选专属预抓取运动；
2. 执行严格直线接近；
3. 执行严格直线抓取位姿；
4. 发送配置的夹爪闭合位置命令；
5. 执行严格直线抬升。

每一步开始前重新验证执行确认新鲜度、计划 ID、目标新鲜度/漂移、当前关节
状态和阶段权限；每一步结束后验证控制器结果、编码器变化及实测终点。任一门控
失败都停止进入下一接触阶段，但不自动发送 torque-off 或失能命令。

### 3.5 终态和审计

- 成功：发布唯一成功终态，并保存快照 ID、候选来源、确定性排序、严格规划
  结果、冻结计划 ID、每段目标/实测关节值、端点误差、夹爪命令和抬升结果。
- 失败：发布最精确的有界原因，释放本次任务执行权限，不把未检查候选标成
  不可达，也不把请求写出标成硬件响应。
- ROS 节点在成功或失败后保持在线，方便继续观察；终态处理不包含自动停止、
  失能或 torque-off。

## 四、不可放宽的硬门控

无论采用哪次路线优化，以下检查不得为了提高成功率而跳过：

- 相机内参、深度、TF 和时间戳有效性；
- 目标点云、包围盒、支撑面和抓取几何有限性；
- 手指、掌部、支撑面及环境碰撞；
- 完整旋转扫掠、关节限位和严格 MoveIt 规划；
- 当前关节状态、目标快照、目标漂移和计划 ID 新鲜度；
- 接触序列各阶段的端点一致性及控制器结果；
- 正向使能后的实测执行确认。

路线优化只能删除重复权威、重复计算和没有新增证据的等待，不能删除上述硬
安全与一致性证明。

接触前观察运动有一项边界明确的例外：控制器 action 判负后，只有新鲜实测
相机—同一目标距离满足既有观察合同，才允许继续近场感知。这不是关节终点
容差放宽，也不适用于任何接触或抬升阶段。

## 六、验证路线

### 6.1 离线验证

1. 先写可复现旧故障的失败测试，再实现最小修复。
2. 分别验证驱动状态机、重连命令准入、任务执行门控、近场单快照选择、严格
   MoveIt 首可达停止、无 MuJoCo/重复仿真/final-refine 调用。
3. 运行受影响套件、完整相关测试、Python 编译、YAML/XML 解析、
   `git diff --check` 和 catkin 构建。
4. 离线验证不得启动 ROS 硬件接口或发送硬件命令。

### 6.2 真机验证

1. 操作者确认机械臂已冷却并上电。
2. 启动完整 ROS 节点，只发送正向 torque-on；驱动应先报告 `PENDING`。
3. 操作者点击“同步当前关节”，再用 GUI 做一个小幅动作。
4. 只有编码器方向一致的实测变化使状态变为 `CONFIRMED` 后，才允许自动抓取。
5. 操作者对准目标，系统生成一份新鲜远场计划并执行第一阶段观察。
6. 若观察位或单次径向修正出现控制器判负，保存控制器错误、目标/实测关节
   值和稳定后的新鲜相机距离；只在原观察闭区间已实际满足时继续。
7. 第二阶段在 `30.0 s` 内形成一次近场融合快照并冻结第一个严格可达计划，
   随即执行接近、抓取、闭合和抬升；否则返回精确原因。
8. 用“成功证明标准”逐项核对运行审计，确认目标实际离开支撑面，才宣布任务
   被证明。

## 技术路线变更记录

### 2026-07-29（初版）

- 建立本技术路线唯一主文档及维护规则。
- 把正向使能请求与编码器实测执行确认分离；加入重连后同步准入，禁止旧目标
  自动重放。
- 将第二阶段定义为单次融合近场快照、权威排序、首个严格 MoveIt 可达即直抓。
- 从生产近场路线移除跨请求稳定等待、MuJoCo 执行否决、任务节点重复仿真和
  final visual refine，阶段预算由 `450 s` 收敛为 `30.0 s`。
- 明确完整成功证据链及“失败不自动 torque-off/stop/disable”的权限边界。

### 2026-07-29（执行确认与近场直抓离线实装）

- 驱动已实现正向使能请求、命令准入和编码器实测响应相互分离的状态机；自动
  抓取只接受新鲜 `CONFIRMED`，重连后的旧目标不能直接重放。
- 生产近场已实现每个任务流只提交一份有效融合快照；该快照提交后不再轮询
  第二份近场快照。
- 当前快照候选在全部硬门控后按确定顺序接受严格 MoveIt 检查，第一个严格
  可达候选立即冻结；无候选、无可达候选和 30 秒到期均有独立终态。
- 计划冻结后立即请求关闭候选流；任务节点直接执行冻结计划，不再调用近场
  MuJoCo、重复任务仿真或 final visual refine。
- 上述路线已完成离线构建、单元/协议回归及配置语法验证。当前状态仅表示
  离线实现成立，不表示真机执行器响应或真实抓取已经得到证明。

### 2026-07-29（第一阶段控制器判负的实测观察合同恢复）

- 真机已证明正向使能后的编码器方向响应能够把执行状态置为 `CONFIRMED`，
  且第一阶段观察轨迹确实产生了大幅、持续的真实关节运动。
- 单次径向修正实际运动后，控制器因 Joint2 终点误差超出既有容差而判负；
  总关节增量接近计划增量不足以证明精确到位，现有 `0.035 rad` 硬件复核上限
  保持不变。
- 第一阶段路线补充边界恢复：只对已严格提交的观察位或单次径向修正，在等待
  反馈稳定后以一份新鲜相机观测复核同一目标的距离。原观察闭区间已实际满足
  才继续一次近场快照，否则仍失败。
- 该恢复不启用驱动端点自动微调，不放宽控制器/关节容差，不增加第二次径向
  修正，也不适用于近场预抓取、接近、抓取、闭合或抬升。

### 2026-07-29（观察恢复真机验证与近场预算缺陷）

- 真机径向修正再次因 Joint2 超出既有终点容差而被控制器判负；任务保持原
  `0.035 rad` 硬件复核上限，等待反馈稳定后取得同一目标的新鲜相机距离。
- 新鲜距离进入原 `[0.180, 0.220] m` 观察闭区间后，任务按路线进入近场；
  这证明观察合同恢复已真实生效，不是容差放宽或总关节增量替代终点验证。
- 本次近场快照与严格 MoveIt 处理跨过了任务侧 30 秒等待终点。任务与远端
  使用不同的计时起点，且已开始的严格检查可跨过远端截止点，导致任务先关闭
  generation、远端结果随后作为过期结果丢弃。
- 这次运行没有形成接触执行计划，不能证明所有当前候选不可达，也没有执行
  接近、抓取、闭合或抬升。现有“近场快照与选择总预算 30 秒”路线要求保持
  不变，但实现尚需统一绝对截止时间并在任务到期前发布精确终态。
